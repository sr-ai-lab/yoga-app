## 0. プロダクトの一言定義

> スマートフォンから **2タップ** で「今日やるヨガ」が決まり、そのままYouTubeで再生できるWebアプリ。

- 対象動画: B-flow / B-flow Studio の **一般公開・無料視聴可能な動画のみ**(旧B-life時代の動画も、公式APIで確認済みの同一チャンネルであるB-flowの一部として扱う)
- 利用者: **主に本人**が利用するが、PublicなWebアプリとして**第三者も利用可能**。ログイン・個人情報なし(誰が使っても端末のlocalStorage以外に何も残らない)
- ホスティング: GitHub Pages(Publicリポジトリ、静的サイト、サーバーレス)
- 保守: Claude Codeによる半自動更新を前提としたデータ・ドキュメント構成

## 1. 中心となるユーザー体験(UX)

### 1.1 基本フロー(2タップ)

```
[トップ画面]
  1タップ目: 時間を選ぶ(10 / 20 / 30 / 45 / 60分)
  2タップ目: モードを選ぶ(6ボタン)
      ↓ 即座に遷移(検索ボタンは置かない)
[結果画面]
  ・20分以下 → 動画1本を提案
  ・30分以上 → 2〜4本の「コース」を提案
  ・「▶ まとめて再生」→ YouTubeアプリで連続再生
  ・「🔀 別の提案」→ 同条件で再抽選
```

### 1.2 モード(6種・確定)

| id | 表示名 | 意図 |
|---|---|---|
| `stretch` | ゆるくほぐす | 低強度で全身をほぐしたい日 |
| `active` | しっかり動く | 元気があり、運動量が欲しい日 |
| `shoulder_neck` | 肩・首 | 肩こり・首・背中上部のケア |
| `hip_lower` | 腰・股関節 | 腰・股関節・骨盤まわりのケア |
| `relax` | リラックス | 就寝前・自律神経を整えたい時 |
| `random` | おまかせ | 条件を考えたくない日 |

**設計方針**: 「朝」「夜」「寝る前」はモードにせず、動画側のタグ + 現在時刻による自動重み付けで扱う(§6.4)。ユーザーは時間帯を入力しない。

### 1.3 操作を減らす工夫

- 前回選択した時間・モードを `localStorage` に保存し、次回アクセス時に選択済み状態で表示する(→ 実質1タップ、同じ内容でよければ0タップで結果へ)
- `localStorage` キー: `bflow.lastTime`, `bflow.lastMode`(値のみ。個人情報なし)
- 詳細設定(部位の追加指定・1本/コース切替など)は結果画面側に折りたたみで置き、トップ画面には出さない

## 2. 画面仕様

画面は2つだけ。SPA(1枚のHTML内で表示切替)とし、ページ遷移・ルーティングライブラリは使わない。

### 2.1 トップ画面

```
┌─────────────────────────┐
│  🐸 今日のヨガ                    │  ← アプリ名(仮)
│                                   │
│  時間                             │
│  [10分][20分][30分][45分][60分]   │  ← 横並びチップ。単一選択
│                                   │
│  今日はどうする?                  │
│  ┌───────┐ ┌───────┐  │
│  │ゆるくほぐす│ │しっかり動く│  │
│  ├───────┤ ├───────┤  │
│  │ 肩・首    │ │ 腰・股関節 │  │  ← 2列×3行の大ボタン
│  ├───────┤ ├───────┤  │     モードタップ=即検索実行
│  │ リラックス │ │ おまかせ  │  │
│  └───────┘ └───────┘  │
└─────────────────────────┘
```

- ボタンは片手の親指で届くサイズ(最小44×44px、実際は幅50%×高さ64px程度)
- 時間チップは前回値が選択済み。モードボタンをタップした瞬間に結果画面へ

### 2.2 結果画面(コース提案時)

```
┌─────────────────────────┐
│  ← もどる                         │
│  30分 × 肩・首                    │  ← 選択条件の確認表示
│                                   │
│  ┌─────────────────┐    │
│  │ [サムネ] 1. ウォームアップ │    │
│  │ 朝ヨガで体をほぐす (5分)   │    │  ← タップで個別にYouTubeへ
│  ├─────────────────┤    │
│  │ [サムネ] 2. メイン         │    │
│  │ 肩こり解消フロー (20分)    │    │
│  ├─────────────────┤    │
│  │ [サムネ] 3. クールダウン   │    │
│  │ 首すっきりストレッチ (6分) │    │
│  └─────────────────┘    │
│  合計 31分                        │
│                                   │
│  ┌─────────────────┐    │
│  │   ▶ まとめて再生          │    │  ← 最重要ボタン。画面下部固定
│  └─────────────────┘    │
│  [ 🔀 別の提案 ]  [ 1本にする ]   │
└─────────────────────────┘
```

- サムネイルは `https://img.youtube.com/vi/{id}/mqdefault.jpg` から取得(データに持たない)
- **まとめて再生**: `https://www.youtube.com/watch_videos?video_ids=ID1,ID2,ID3` を新規タブで開く
  - スマートフォンではYouTubeアプリが起動し、指定順の一時リストとして再生されることを確認済み
  - フォールバック: この方式が動かない環境でも、各カードのタップで個別に動画を開けるため機能は損なわれない
- **別の提案**: 同条件で再抽選(§6.5のランダム性により別の結果が出る)
- **1本にする / コースにする**: 30分以上のときのみ表示されるトグル。単発の長い動画1本を希望する日に対応
- 単発提案時(20分以下)は動画カード1枚+「▶ 再生」+「🔀 別の提案」のみのシンプルな表示

### 2.3 スマートフォン対応・PWA

- ビューポート幅375px基準のモバイルファーストCSS。メディアクエリでPC閲覧時も破綻しない程度に整える
- `manifest.json` を置き、ホーム画面追加でスタンドアロン表示(アプリ風)にする
- iOS Safari向けに `apple-touch-icon` と `apple-mobile-web-app-capable` メタタグも設定
- Service Worker(オフライン対応)は**実装しない**。再生はYouTubeでオンライン前提のため不要
- スタンドアロン表示時の外部リンク遷移(`watch_videos`)の挙動については §13 の追加検証項目を参照

## 4. データ設計

### 4.1 videos.json

```json
{
  "schema_version": 1,
  "updated": "2026-08-14",
  "videos": [
    {
      "id": "AbCdEfGhIjK",
      "title": "朝ヨガで心地よく1日を始める☀ 初心者にもおすすめ",
      "channel": "b-flow",
      "duration_min": 12,
      "intensity": 1,
      "type": "main",
      "tags": ["朝", "全身", "初心者", "リフレッシュ"]
    }
  ]
}
```

| 項目 | 型 | 必須 | 説明 |
|---|---|---|---|
| `id` | string | ✔ | YouTube動画ID(11文字)。URL・サムネイルはここから生成 |
| `title` | string | ✔ | 動画タイトル(そのまま転記) |
| `channel` | string | ✔ | `b-flow` / `b-flow-studio` のいずれか(旧B-life時代の動画も`b-flow`に含む) |
| `duration_min` | number | ✔ | 分単位・整数(四捨五入) |
| `intensity` | number | ✔ | 1=ゆるい / 2=ふつう / 3=しっかり |
| `type` | string | ✔ | `warmup` / `main` / `cooldown` / `meditation` |
| `tags` | string[] | ✔ | vocabulary.json記載の語のみ。1〜5個 |

**持たない項目とその理由**:
- URL → `https://www.youtube.com/watch?v={id}` で生成(表記ゆれ・重複防止)
- サムネイルURL → `https://img.youtube.com/vi/{id}/mqdefault.jpg` で生成
- 公開状態・無料視聴可否 → 「videos.jsonに載っている=一般公開・無料視聴可能と確認済み」という運用ルールにする。視聴不可になった動画はリストから削除する(履歴はgitに残る)
- 説明文・再生数など → 推薦に使わないため持たない
- 確認日時(`verified_date`等) → MVPでは追加しない。将来、視聴可否の再確認運用を自動化する必要が出た場合に検討する

### 4.2 type(動画の役割)の判定基準

| type | 基準 |
|---|---|
| `warmup` | 5〜12分程度。準備運動・目覚まし系。単体でも成立するが短い |
| `main` | 10分以上。その日の中心となるフロー・レッスン |
| `cooldown` | 10分以下。ストレッチ・整理体操・就寝前系 |
| `meditation` | 瞑想・呼吸法のみで、ほぼ体を動かさないもの |

1本の動画は必ず1つのtypeを持つ。迷ったら `main`。短い(≦10分)リラックス系は `cooldown` を優先する(コース終端の候補を確保するため)。

### 4.3 vocabulary.json(統制語彙)

タグはこのファイルに記載された語**のみ**使用可能。バリデーションで強制する。

```json
{
  "schema_version": 1,
  "categories": {
    "部位": ["肩", "首", "背中", "腰", "股関節", "骨盤", "脚", "体幹", "顔", "全身"],
    "時間帯": ["朝", "夜", "寝る前"],
    "目的": ["リラックス", "リフレッシュ", "疲労回復", "自律神経", "柔軟性", "筋力", "デトックス", "むくみ"],
    "レベル": ["初心者", "中級"]
  }
}
```

- 合計23語。**MVP(100本)の検証期間中のみ追加・変更可**。全件展開後は原則凍結する
- 語を追加する場合は、UPDATE.mdの分類ルールにも判定基準を追記すること
- 同義語(例:「肩こり」)はタイトルに現れても、タグとしては正規形(「肩」)に寄せる

### 4.4 modes.json(モード定義=推薦の重み)

モードの挙動をデータとして持つことで、**アプリのコードを変更せずに推薦の調整ができる**。

```json
{

  "modes": [
    {
      "id": "stretch",
      "label": "ゆるくほぐす",
      "intensity": { "1": 10, "2": 4, "3": 0 },
      "tag_weights": { "全身": 5, "柔軟性": 5, "疲労回復": 4, "リフレッシュ": 3 },
      "main_types": ["main", "cooldown"]
    },
    {
      "id": "active",
      "label": "しっかり動く",
      "intensity": { "1": 0, "2": 5, "3": 10 },
      "tag_weights": { "筋力": 5, "体幹": 5, "全身": 4, "デトックス": 3 },
      "main_types": ["main"]
    },
    {
      "id": "shoulder_neck",
      "label": "肩・首",
      "intensity": { "1": 6, "2": 6, "3": 2 },
      "tag_weights": { "肩": 10, "首": 10, "背中": 5 },
      "main_types": ["main", "cooldown"]
    },
    {
      "id": "hip_lower",
      "label": "腰・股関節",
      "intensity": { "1": 6, "2": 6, "3": 2 },
      "tag_weights": { "腰": 10, "股関節": 10, "骨盤": 8, "脚": 4 },
      "main_types": ["main", "cooldown"]
    },
    {
      "id": "relax",
      "label": "リラックス",
      "intensity": { "1": 10, "2": 3, "3": 0 },
      "tag_weights": { "リラックス": 10, "自律神経": 8, "寝る前": 6, "疲労回復": 4 },
      "main_types": ["main", "cooldown", "meditation"]
    },
    {
      "id": "random",
      "label": "おまかせ",
      "intensity": { "1": 5, "2": 5, "3": 5 },
      "tag_weights": {},

```

- `intensity`: 強度ごとの加点(0=そのモードでは実質除外)

- `main_types`: コースの「メイン枠」に許可するtype

## 5. 推薦ロジック(単発)

### 5.1 スコアリング

```
入力: minutes(選択時間), mode(選択モード), now(現在時刻)

candidates = videos のうち
  ・duration_min が minutes の ±15%(最低±3分)以内
  ・mode.intensity[v.intensity] > 0

score(v) =
    mode.intensity[v.intensity]                  // 強度適合
  + Σ mode.tag_weights[t] for t in v.tags        // タグ適合
  + timeOfDayBonus(v.tags, now)                  // 時間帯ボーナス(§4.4)
  + durationFit(v, minutes)                      // 時間ぴったり度: 0〜3点
  + jitter()                                     // 乱数 0〜2点(§5.2)
```

- `durationFit`: |duration_min − minutes| が0なら3点、以降1分差ごとに−1点(下限0)
- 候補が0件の場合は時間許容幅を±30%に広げて再検索。それでも0件なら「条件に合う動画が見つかりませんでした」と表示し、時間かモードの変更を促す

### 5.2 ランダム性(毎日使うための設計)

決定的に最高スコア1本を返すと毎回同じ動画になり、飽きて使われなくなる。

- スコア上位 **5件** を候補プールとし、スコアに比例した重み付きランダムで1本選ぶ
- 「🔀 別の提案」は同じプールから**直前の提案を除外して**再抽選
- セッション内で提案済みのIDは記憶し、プールが尽きるまで重複させない(ページ再読み込みでリセット)

## 6. コース生成ロジック(複数動画の組み合わせ)

### 6.1 発動条件

- 選択時間が **30分以上** → デフォルトでコース提案(「1本にする」で単発に切替可)
- 20分以下 → 常に単発

### 6.2 スロットテンプレート

「自然な流れ」= 強度が山型(上がって下がる)+ 最後はリラックス系で終わる、をテンプレートで表現する。

| 選択時間 | スロット構成(目安分数) |
|---|---|
| 30分 | warmup(5) → main(18) → cooldown(7) |
| 45分 | warmup(8) → main(25) → cooldown(10) |
| 60分 | warmup(10) → main(22) → main(18) → cooldown(10) |

### 6.3 スロットの埋め方

```
1. main枠: §5のスコアリングをそのまま使って選ぶ
   (時間条件はスロット目安分数±30%、type ∈ mode.main_types)
2. warmup枠: type=warmup、intensity ≦ mainのintensity、
   スロット分数±3分。モードのtag_weightsも適用(肩・首モードなら
   肩系ウォームアップが選ばれやすくなる)
3. cooldown枠: type ∈ {cooldown, meditation}、intensity=1優先、
   「リラックス」「寝る前」タグに加点
4. 制約:
   ・同一動画をコース内で重複させない
   ・強度の並びが「上がって下がる」山型になっているか検査
     (warmup ≦ main ≧ cooldown を満たさない組み合わせは棄却して再抽選)
   ・合計時間が 選択時間 −5分 〜 +3分 に収まること
   ・上記の制約を満たす組み合わせが見つかるまで再抽選するが、
     **再抽選は最大20回まで**とする。20回に達しても条件を満たす
     組み合わせが見つからない場合は、無限ループ・UIブロックを避けるため
     手順5のフォールバックへ進む
5. 埋まらないスロットがある場合(手順4の再抽選上限に達した場合を含む):
   ・60分でmain2が埋まらない → main1を長い動画に差し替えて3本構成に
   ・warmupが埋まらない → mainを長めにして2本構成(main→cooldown)に
   ・最終手段: 単発提案にフォールバック
```

### 6.4 まとめて再生URL

```
https://www.youtube.com/watch_videos?video_ids={id1},{id2},{id3}
```

- 動作想定は2系統ある。**実装時に両方を実機で検証すること**(§13 Step 3):
  - **YouTubeアプリあり**: アプリが起動し、指定順の一時リスト(Untitled List)として連続再生される(実機確認済み)
  - **YouTubeアプリなし**: ブラウザ版YouTube(m.youtube.com)で一時リストとして開かれることを想定。実機で連続再生の挙動を確認する
- **非公式エンドポイントである**ため、将来無効化されるリスクをコード内コメントとREADMEに明記する
- **いずれの環境でも**、フォールバックとして各動画の個別リンクを常に結果画面に表示する(§2.2)。第三者の利用環境は制御できないため、まとめて再生が機能しない環境でもアプリとして成立することを設計上の前提とする
- PWAとしてホーム画面から起動した場合(スタンドアロン表示)の挙動は別途 §13 で検証する

## 7. 技術構成

| 項目 | 選定 | 理由 |
|---|---|---|
| フロントエンド | 素のHTML/CSS/JavaScript(ES2020+) | ビルド不要、push=デプロイ。数か月後にClaude Codeが読んでも構造=説明になる。依存更新の保守が発生しない |

| ホスティング | GitHub Pages(mainブランチ / ルート) | 無料・サーバーレス・push連動 |

**アプリ本体でやらないこと**: npm install、バンドラー、TypeScript、CSSフレームワーク、アナリティクス、Cookie。

## 9. 動画リストの更新フロー

### 9.1 全体像

```
① 新着検知     : チャンネルRSSフィードを確認(APIキー不要・最新15本)
② 情報取得     : 新着分のみ YouTube Data API v3 で duration 等を取得
③ 視聴可否確認 : oEmbed等で一般公開・無料視聴可を確認(不明なものは人間が実際に開いて確認)
④ 分類         : Claude Codeがタイトル等から intensity / type / tags の候補を提案
⑤ 人間の確認   : 分類候補を確認・修正(このステップは自動化しない)
⑥ 追記         : videos.json に追加
⑦ 検証         : scripts/validate.mjs で機械チェック
⑧ 反映         : git commit & push → GitHub Pagesに自動反映
```

- 外部API(YouTube Data API)は**②の更新時のみ**使用。アプリの通常利用では一切使わない
- APIキーはローカルの `.env` に置き、`.gitignore` で除外。リポジトリには `.env.example`(キー名のみ記載)を置く

### 9.2 scripts/config.json

```json
{
  "channels": [
    { "name": "b-flow",        "channel_id": "UCd0pUnH7i5CM-Y8xRe7cZVg" },
    { "name": "b-flow-studio", "channel_id": "UCaf8CNoK0GuCvjPDeint_1g" }
  ],
  "rss_url_template": "https://www.youtube.com/feeds/videos.xml?channel_id={channel_id}"
}
```

channel IDはYouTube Data API(`channels.list`, `forHandle=bflowyoga` / `forHandle=bflowstudio`)により公式確認済み(2026-08-14)。channel IDは公開識別子でありAPIキーのような秘密情報ではないため、本ドキュメント・リポジトリに直接記載してよいものとして扱う。

### 9.3 fetch-new.mjs の仕様

```
入力: なし(config.jsonと.envを読む)
処理:
  1. 各チャンネルのRSSを取得し、動画ID・タイトル・公開日を得る
  2. videos.json に存在しないIDのみ抽出(重複検出)
  3. YouTube Data API (videos.list, part=contentDetails,status,snippet) で
     duration・公開状態を取得
  4. duration を分に丸め、下書きレコードを生成
     (intensity / type / tags は "TODO" のまま)
出力: scripts/inbox.json に下書きを書き出し、件数を表示
備考: RSSは直近15本のみ。それより古い動画の一括取り込みは
      初回構築時に別途プレイリストAPI(uploads playlist)で行う
```

### 9.4 validate.mjs の仕様(§9.1の⑦)

チェック項目:

1. `id`: 11文字の英数字`-_`、全レコードで一意
2. 必須項目がすべて存在し、型が正しい
3. `channel` が config.json のチャンネル名のいずれか
4. `duration_min` が 1〜120 の整数
5. `intensity` が 1 / 2 / 3
6. `type` が warmup / main / cooldown / meditation
7. `tags` が1〜5個、すべて vocabulary.json に存在する語
8. (オプション `--check-live`)各動画のoEmbedを叩き、視聴不可になった動画を警告
   - `https://www.youtube.com/oembed?url=https://www.youtube.com/watch?v={id}&format=json`
   - 実装時にメンバー限定動画で挙動を検証すること。判定できない場合は「警告リストを人間が目視確認」する運用にする

エラーがあれば行番号つきで表示し、終了コード1を返す(pushの前に必ず実行する運用)。

### 9.5 初回データ構築(MVP: 100本)

1. 各チャンネルのuploadsプレイリストから動画一覧を取得(YouTube Data API)
2. **直近1〜2年 + 明らかに定番の動画** から約100本を選定
3. Claude Codeがタイトルから分類候補を一括生成 → 人間が確認・修正
4. この100本で **タグ設計・分類基準・推薦精度を検証する**(検証期間)
5. 検証で分類ルールを修正したら vocabulary.json と UPDATE.md に反映
6. 問題がなくなってから全件展開。**全件展開後のタグ体系変更は原則行わない**

## 11. セキュリティ・Publicリポジトリ上の注意

1. **APIキー**: `.env` はコミット禁止(`.gitignore` に明記)。`.env.example` にはキー名のみ。万一コミットした場合はキーを失効・再発行する(履歴削除だけでは不十分)
2. **個人情報**: アプリはログイン・氏名・連絡先を一切扱わない。localStorageに保存するのは時間・モードの選択値のみ
3. **YouTubeデータの扱い**: リポジトリに保存するのは「動画ID・タイトル・長さ」という事実データと**自作の分類**のみ。APIレスポンスの丸ごと保存・再配布はしない。この整理をREADMEに明記する
4. **著作権**: 動画の埋め込み・ダウンロードはせず、YouTube公式ページ/アプリへのリンクのみ。サムネイルもYouTube提供の公式URLを参照するだけ
5. **無料視聴可否の担保**: 「videos.jsonに載せる前に人間が視聴可否を確認する」を運用ルールとし、UPDATE.mdの手順に組み込み済み(§10.1 手順2)
6. **第三者利用に関する表示**: 第三者も利用可能なPublicアプリとするため、READMEおよびアプリのフッターに「本アプリは非公式の個人プロジェクトであり、B-flow / B-flow Studio 各チャンネルとは無関係であること」「動画の権利は各チャンネルに帰属し、本アプリはYouTubeへのリンク集であること」を明記する。チャンネル名をアプリ名に含める場合は誤認を招かない表現にする(§14の名称決定時に考慮)
7. **Public化前のGit履歴チェック**: 現在はPrivateリポジトリで開発し、完成後にPublicへ切り替える運用とする。切り替える前に、リポジトリの全コミット履歴を対象に秘密情報(APIキー・トークン等)が含まれていないかを必ず確認する。
   - `git log -p -- .env` 等、APIキーを含みうるファイルの履歴を直接確認する
   - 可能であれば gitleaks 等のシークレットスキャンツールをリポジトリ全体に対して実行する
   - 万一検出した場合は、該当キーを失効・再発行したうえで対応する(履歴からの削除だけでは元のキー自体は無効化されないため、失効が必須)
   - この手順はREADMEの「Public化手順」にもチェックリストとして明記する(§8手順0)

## 13. Claude Codeへの実装依頼の進め方(推奨)

一度に全部を依頼せず、動作確認できる単位で分ける:

1. **Step 1**: ファイル構成の骨組み + サンプル動画10本のvideos.json + トップ画面UI
2. **Step 2**: 単発推薦ロジック + 結果画面
3. **Step 3**: コース生成 + まとめて再生
4. **Step 4**: manifest.json / localStorage / 仕上げ
5. **Step 5**: scripts/(fetch-new, validate)+ UPDATE.md / CLAUDE.md / README
6. **Step 6**: GitHub Pages公開 → 実機(スマートフォン)確認
7. **Step 7**: 初回100本のデータ構築(§9.5)

各Stepの完了時にスマートフォン実機で確認してから次に進むこと。特にStep 3の watch_videos URL は実機確認が必須で、以下の環境で検証する:

- **YouTubeアプリありの端末**: アプリが起動し、指定順で連続再生されること
- **YouTubeアプリなしの端末**(またはアプリを無効化した状態): ブラウザ版YouTubeで一時リストが開き再生できること

いずれか一方でも期待通り動かない場合でも、個別動画リンクのフォールバックが表示されていれば機能要件は満たすものとする。

**追加検証(Step 4完了後)**: manifest.json実装後、ホーム画面に追加してスタンドアロン表示(PWAとして起動した状態)からも「まとめて再生」を実行し、YouTubeアプリまたはブラウザへ正しく遷移することを確認する。スタンドアロン表示のWebView内ではリンク遷移の挙動が通常のブラウザタブと異なる場合があり、Step 3時点(通常のブラウザタブ)での検証だけでは不十分となる可能性があるため、別途確認する。いずれの環境でも個別リンクのフォールバックが機能していれば要件は満たされる。
